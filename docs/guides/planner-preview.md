# Imaging planner preview (`/planner`)

Reachable by URL only; not in the header, `noindex`. All state is in the browser (localStorage keys `fpo-planner-profile-v1`, `fpo-planner-captured-v1`, `fpo-planner-plans-v1`, `fpo-planner-selection-v1`). The page has two tabs, "Plan" (the default) and "Gear and site", addressed as `#plan` and `#gear`; a link to anything inside Gear and site (`#horizon`, `#gear-heading`) opens that tab first. The sign-in control is in the header row, beside the title. The planner itself has no server code; the optional Google sign-in does (see Sign-in and owner gate).

## Manual check

1. `npm run dev`, open `/planner`.
2. Date defaults to tonight at the site (from its longitude; before 06:00 site time it is the night that began yesterday), whatever the browser's zone. Times are shown in the browser's time zone, because the profile's site has no time zone field.
3. Horizon editor (Start, End, Height). Typing and sliding edit a draft; only "Save horizon" stores it.
   - On the Plan tab open "Night and horizon" in the open plan and click "Edit horizon" next to the "Horizon:" line: the Gear and site tab opens at the editor.
   - Type `200` in Start, key by key: the slider and the polar chart in the editor follow as soon as the text is a valid whole number. The status line says "Unsaved changes". The "Horizon:" line, the target list and the altitude chart plan from the saved arc, so they change only when you click "Save horizon" (or press Enter in a box while the form is valid). Nothing is stored before that.
   - A slider follows its own box whenever the box holds a valid number, so the arrow keys step one degree at a time across the other end (Start 318, then ArrowRight: 319, 320, 321 ...).
   - Type `500` in Start: a line under the box says "Use 0 to 360 degrees.", the slider goes back to the saved Start and the plan never left it, "Save horizon" is greyed and the status line says "Fix the highlighted box to save". Same for `361`, for `91` or `95` in Height ("Use 0 to 90 degrees."), for an empty box, and for `1.5` ("Whole degrees only.").
   - Type `320` in Start while End is 320: "Start and End must differ." under both boxes.
   - Leaving a box (Tab, a click elsewhere) and Escape do nothing. Pressing Enter in a box saves only if the form is valid.
   - The buttons and the target list keep their page position on every key, because the list does not follow the draft and every message line has its height reserved. So the first click on "Discard changes", "Use sample horizon", "Clear horizon" or "Save horizon" works right after bad typing. "Discard changes" puts the three boxes back to the saved arc.
   - "Use sample horizon" loads the sample arc into the boxes as an unsaved draft ("Discard changes" undoes it) and puts Minimum altitude back to 20. The whole-profile wipe is "Reset all" in the Profile section.
   - A different site, an import and "Reset all" also set the boxes from the saved arc and Minimum altitude to 20; nothing typed survives.
   - Tab order: for each zone card in turn (Start box, Start slider, End box, End slider, Height box, Height slider, Remove zone), then Add another zone, Save, Discard, Use sample horizon, Clear horizon, "Horizon as a table". The compass has no tab stop.
   - Layout: the zone cards sit above the compass in a grid of at most 2 columns by 2 rows (1 column on a phone); Add, Save, Discard and Use sample and the summary text sit beside the compass (below it on a phone).
   - Zones: up to 4, each Start and End from 0 to 360 whatever the other zones hold (360 is north and is saved as 0); Height 0 to 90.
   - Add another zone rule: the new zone starts where the last zone ended, is 30 degrees wide (wrapping past 360) and has the last zone's height. It is never moved to avoid another zone. The first zone is 90 to 180 at 30.
   - Overlap is allowed. The blocked region is all zones together; where zones overlap or touch, the highest of them applies (a target is blocked if any zone blocks it). The chart fills are translucent so overlaps get darker, each sector carries its zone number, and the summary, the chart description and the table say which zones overlap and where. Profiles saved under the old no-overlap rule load unchanged; the stored shape (a list of start, end, height) did not change, so the profile version stays 3.
   - Minimum altitude (in the sticky strip) works on its own: it applies as soon as the text is a whole number from 0 to 89, with no Save. While it is invalid the plan keeps the value that was in effect when the current run of typing began, never a half-typed prefix. A run ends when the box gets focus, on Enter, or after a pause of about 0.6 s with no keystroke; only then does the kept value move to the current valid number. So emptying the box with Backspace (45 in effect, or the default 20) still plans with 45 (or 20), and within one run of typing the message names the value from before the run, and the line under the box names it ("Use 0 to 89. Planning with 30 until fixed."). Its message slot reserves two lines.
   - Bad Minimum altitude does not block "Save horizon".
4. Raise the height to 80 and save: southern targets drop out of the list. "Clear horizon" is also a draft: badge "Horizon not set" and the flat minimum altitude in each "why" once saved; "Discard changes" brings the arc back.
5. "Save horizon" then reload: the arc persists, status line empty. "Reset all" (Profile section of Gear and site) asks first, naming what it clears (sites, gear, trains, horizon, every saved plan, captured ticks, the remembered site and train); "Cancel" changes nothing, and confirming restores the default.
6. Targets: pick the train "C11 f/10 + ASI2600MC Duo". Targets that do not fit the field are not listed. Tick "Show targets that do not fit": they appear below every row that fits, and their text reads "Does not fit this setup (...)" under "Why it is listed". Rows that fit still read "Why recommended".
7. "Export CSV": header row, one row per listed target, names with commas quoted.
8. Filter (the sticky strip; the Exposure module is gone from the page, per-target exposure comes back in the plan's rows):
   - The filter belongs to the train and is chosen in one place: the train's form in Gear ("No filter" and the twelve sample filters). The strip shows "Filter: <name>" under the Train box (a smart scope reads "built in") and a "Change this train" button that opens that train's form with its Name focused; a warning's "Change the filter" does the same. The choice is saved with the profile and shows again after a reload; "Reset all" loads the sample list (it also resets the horizon).
9. Import a profile with `latitude: 120`: the error names the site and the box in words (`Site "<name>", latitude: Enter a latitude between -90 and 90 deg. It is 120.`), with no field path.
10. Solar system (rows of the target list; the profile's first train is the deep-sky train, pick "C11 + ASI676MC (solar system)" for the planetary one):
   - The group "Solar system up tonight (N)" sits above the deep-sky targets and counts only the bodies that are up (the Moon too when it is up). It is closed on a deep-sky train and open on a planetary train. Type = Solar system shows only the group, open, for that view; going back to All restores the rule, unless you opened or closed the group by hand.
   - Inside it, "Not up tonight (N)" (closed while something is up) lists the bodies that are not clear on the chosen night (Venus, Mercury, an early or down Moon, any of the eight) as compact rows marked "Not clear tonight": no rank number, no score, never counted as up. On 2026-11-14 Venus, Mercury and the Moon are there; Mars, Jupiter, Saturn, Uranus and Neptune are up.
   - A row says "Solar system" once (the meta line); the fit column gives the apparent diameter at the middle of the night. A row opens in place: the list detail (why, usable window, peak, Moon, Captured, the altitude chart) and then the body's own detail. The search row for a body ("Show Venus detail") opens the same detail, up or not.
   - The body detail holds apparent diameter (and its size in pixels on the chosen train), phase or illuminated fraction, opposition or greatest elongation (nearest one, in days), culmination, minutes clear of your horizon (from the saved arc) and how many of them are above the no-ADC altitude, Saturn's ring tilt (the size only; the library does not say which face shows), the clip length limit, the image scale, and for the Moon the phase name and the mosaic. Each label says computed, or computed with a named basis (rotation period sourced, seeing assumed). The 21-item lucky-imaging checklist is behind its own closed fold ("Lucky-imaging checklist: Jupiter (21 items)"); ticks are kept per body while the page is open and are not saved.
   - The windows use the same astronomical night as the target list. Venus, Mercury and the early Moon are twilight objects and may show as not clear when they could be imaged earlier; that is not computed. There is no Jupiter Great Red Spot transit (no verified longitude model).
   - Export CSV: the Type column says "Solar system" for the Moon and planets (the name column keeps the body's own name); the column headed "Solar system" is the yes/no flag.
   - The altitude chart for the open body has a title, a description and a table behind "Altitude as a table".
   - The checklist (Space ticks a box; ticks are not saved) ends each line with its basis: computed, sourced, assumption, practice or not verified. It names the scope and camera of the chosen train from the profile (pick the ASI533MC reducer train: it says ASI533MC, not ASI676MC). The exposure line is per body: Jupiter keeps a 10 ms assumption; Saturn, Mars, Uranus and Neptune quote one university club's published setting as the order of magnitude (sourced; Saturn, Uranus and Neptune are told they need longer than Jupiter); Venus, Mercury and the Moon give no number. Clip length (up to a number of seconds, from rotation) and session length (about 30 minutes at the telescope) are separate lines. ASIAIR appears once, as not verified. The train lines say to start native; the 2.5x Powermate row is nominal because the Powermate is a 1.25 inch eyepiece amplifier with no stated camera spacing.
   - Check the numbers against a second source: `src/planner/planets/horizons.fixture.json` holds JPL Horizons values for the sample site (diameter, illuminated fraction, azimuth, altitude, elongation, transit times) and `planets.test.ts` compares them.
11. Night timeline (the open plan's closed part; its slots are the plan's targets in the plan's order, on the plan's train and its filter):
   - Add targets to the plan from Find a target or the list. The timeline has no add box and no Up and Down: the plan's order is the plan's, and "Plan my night with AI" then "Use this plan" is the way to change it. Up to eight targets are scheduled; with more, a line says how many are not.
   - Each slot shows start and end (estimate), the light it plans (sub length, count, minutes, from the exposure module), the minutes of changeover before it, and chips for what needs a look. Per slot: the exposure preset it uses (read-only here; change it on the target's row), a note (200 characters) and Details. To remove a target use the [x] on its row in the plan. "Imaging can start at" is the plan's start time. When a slot's sub differs from its row's, a line says so: it names the 500-sub cap as the cause only when the row's sub was lengthened for it, otherwise it says the slot is planned for the sky during its own time.
   - Changeover between slots (all estimates, `src/planner/itinerary/constants.ts`): slew and centre 3 min; refocus 3 min. Setup (30 min) is before the first slot and not counted. (Filter and train changes are in the engine; the page has one train and one filter per plan, so they do not occur.)
   - Warnings: "Waits" (note: the target is not clear yet, a planet is waiting to be centred on its highest point, or a short first window is skipped for a later one), "Overlaps window" (warning: the slots before used part of a window that closes, so too little is left for the preset; it does not show while the light still reaches the preset's range), "Cut short", "Meridian flip" (the exposure module's flip time, for planets as well as deep-sky targets: the planet's real crossing inside the slot), "No time" (the window closed before this slot's turn; the sentence says when a changeover ran past the close). The Details box shows the sentences; it is as tall as the longest possible set, so nothing moves.
   - Try Orion Nebula then Triangulum Galaxy on 2026-12-15 with the C11 + 0.7x reducer + ASI533MC train: the second slot overlaps its window (Triangulum closes 07:11 UTC; Orion ends 07:00). Put Triangulum first (remove and add again, or use Plan my night with AI): the overlap goes.
   - A planet slot is 20 minutes of clips, centred on the planet's highest point where its window allows. Add Neptune alone: its slot crosses the meridian (01:56 UTC), shows "Meridian flip" and is 30 minutes long (20 of clips and the 10 minute flip). The Moon slot crosses nothing and takes 20.
   - "Why this order" is one sentence: sorted by when each target clears the horizon, or the plan's own order with the first pair that is out of order named.
   - The slots are saved with the plan in `fpo-planner-plans-v1`. A browser that still holds the old My plan list or night itinerary (`fpo-planner-my-plan-v1`, `fpo-planner-itinerary-v1`) moves them, once, into one plan named "My plan": the list's order, each slot's mode as the target's preset, its note, the start time; the old keys are then removed. The old night timeline's order is kept: its slots come first, in slot order, then the rest of My plan in its order, so the first 8 targets are the old timeline. Two slots for one target merge into one (the first slot's preset, the notes joined within 200 characters) and the page says so; targets cut by the 50 limit are named. A damaged old copy is said once and removed; an old key the browser could not read is left in place and moved the next time.
   - Saved plans are never removed by the page when they cannot be used whole. A version above 1 reads "made by a newer version of the planner": the stored text is not touched or overwritten, what you do is not saved, and "Replace the saved plans" (after copying what is stored at that moment to a backup) is the user's choice. Backups: every copy has its own key, `fpo-planner-plans-v1.bak.<epoch-ms>`, none is ever overwritten, and the newest 5 are kept (the single `fpo-planner-plans-v1.bak` of earlier versions counts as the oldest). Damaged text starts one empty plan, is copied to a backup and stays where it is until the next save. One plan with an unknown preset (set to Balanced) or a bad date (set to today) is repaired alone, one that cannot be read is left out alone and named, and the other plans load; the original text is copied to the backup first. Two tabs: a plans change in another tab shows up here, and a tab re-reads before it writes. A tab that is holding plans back follows the other tab (storage events, and a re-check when the tab gets focus): readable plans are taken up when nothing was changed here, otherwise the box updates and Replace backs up whatever is stored then.
   - A plan whose night has passed shows one line at the top of the open plan, "This plan is for <date>, which has passed." with "Move to tonight"; nothing changes until it is pressed, and it keeps the targets, presets, site and train.
   - Plans are not part of the profile export and cannot be recovered after "Reset all" (it also removes every backup copy). A plans download and import is a later stage.

12. Best [type] tonight (the list's one Type selector):
   - Type offers All, Galaxies, Nebulae (emission, reflection, HII, dark, and clusters with nebulae), Planetary nebulae, Globular clusters, Open clusters, Supernova remnants, Galaxy groups and pairs, and Solar system. There is no choice for double stars or asterisms (search finds them; asterisms are still in All).
   - Each deep-sky option shows how many fit the frame and are up for the chosen night, site, horizon and train ("Globular clusters · 12 fit tonight"); All and Solar system show how many are up. A type that is up but has nothing that fits reads "Supernova remnants · 7 up, none fit this frame" and can be picked: the list says "No supernova remnants that fit this frame are up tonight: 7 larger than this frame." and "Show targets that do not fit" lists them. Only a type with nothing up at all reads "none up tonight" and cannot be picked (its title says why), unless it is the chosen one. The counts go while a new night or train is being ranked and come back with it.
   - A type is ranked over the whole catalog by the same ranker (the type goes in the request), best to worst, with the same score, why line and fit rule; it is never the mixed best 100 filtered afterwards. "Show 10 more" pages up to 100. All shows the mixed list as before. All and Solar system share one ranking.
   - The heading follows: "Best globular clusters for tonight", or "... for Sat 21 Nov" on another date. A type with no rows says why: nothing of it is up long enough, or what is up is larger (or too small) for this frame, and the "Show targets that do not fit" box lists those for that type.
   - "Add top 3 to the plan" (above the list) adds the first three of the list that are not in the open plan, in order, and says what it added. It is disabled, with the reason, when the plan is full (50) or the whole list is already in it; with room for fewer than three it adds what fits and says how many were not added.
   - The chosen type is remembered with the site and train (`fpo-planner-selection-v1`, field `typeId`); a type that no longer exists opens as All. "Reset all" and an import put it back to All.

13. Gear (the Gear and site tab; Gear is first on the tab, on a phone too; Planner settings, the horizon editor, Profile and Reset all sit below it):
   - One Gear section with a class picker: Trains, Scopes (scopes and smart scopes together, smart ones tagged), Cameras, Filters, Accessories, Sites. Each button shows its count. It opens on Trains; "Change or find a site" in the strip opens Sites on that site's form.
   - Each class is a list of cards: name, its main numbers, and one line saying what uses it ("Used by 3 trains: ...", "Used by 1 plan: ...", or "Not used."). Add is at the bottom of the list ("Add scope" and "Add smart scope" in Scopes) and opens the new card's form. Change opens that card's form (one Save, one Close); a refused value names its box and changes nothing.
   - Every number has one real range, defined once in `src/planner/profile/limits.ts` and read by the form, the validator, the store, the engine and every message: focal length 10 to 10,000 mm (a 14 mm wide-field lens is in), aperture 5 to 1,000 mm (a 14 mm f/2.8 lens has 5 mm), pixel size 1 to 25 µm (24 µm CCDs are in), sensor width and height 100 to 20,000 px (whole), focal length factor 0.2 to 5, whole-scope focal length 50 to 10,000 mm, filter size 10 to 100 mm, passband width and narrowest band 0.1 to 1,000 nm, fastest rated focal ratio 0.5 to 30, largest incident angle 0.1 to 89 deg (the last four are this build's own choice). Each box shows its range after its label. A name is at most 80 characters, not empty, and not another item's name in the same class. A refused box says so in a sentence ("Focal length: 99999 is outside the allowed range. Enter a focal length between 10 and 10,000 mm.").
   - A profile already stored with a gear value that is outside its range, negative, zero, empty or text (an older or damaged save) opens as it is: the value is kept, its card says "... is outside 10 to 10,000 mm, so the planner does not use it. Change it and press Save." (an enormous one reads "an impossibly large number"; text reads "saved as "abc", which is not a number"), a note on load says how many, and the plan's row says which camera or scope lacks the number. Saving other gear is not blocked. An import is stricter: it refuses such a value and names the item and the box in words. A stored site with a latitude, longitude, elevation or Bortle class outside its range cannot be used: the page says which site and box, shows the sample, and keeps the saved copy until you save a change in Gear, which replaces it.
   - Remove deletes an unused item at once and says so, with "Undo" in the status line for one step (until anything else changes). A used one is not removed: the card says "Not removed. Used by 2 trains: ... Change or remove those trains first." A site or train a saved plan uses says "Open that plan and choose another site (train) first." with an "Open <plan>" button (only for that refusal: the last site says "The planner needs at least one site." with no button). Undo says what came back ("Put back <name>."). The sample's own hidden example plan never blocks a removal; it goes with the site or train. The last site and the last train always stay.
   - Keyboard: Save keeps the keyboard on Save; Add puts it in the new form's Name; Escape closes an open form and returns to the card's Change. A train's form says "Used by N plans: ... Their exposure follows this change." when plans use it.
   - Two tabs: gear saved in another tab is shown here at once ("Another tab changed your gear. This page now shows it."). An edit made before that arrived is not made: the status never says "Saved", "Removed" or "Added" for it, and the other tab's gear is shown. The horizon Save makes the same check and does not write over the other tab's gear. Only Import replaces the whole profile, by intent.
   - Trains are cards with a chain of coloured parts: Scope, Accessory (reducer, HyperStar), Camera, Filter (a smart scope is one part). It shows "..." for now." with "Keep ..." and (for a train) "Change train". Nothing stored changes until you press one. The AI flyout shows the same note in step 1 and does not offer to ask until you keep or change; print and the plan CSV carry it too (a "Warning" column).
   - Nothing about the stored shape changed (profile version 3), so a saved profile of any version loads with all its gear. A camera with no pixel size stays valid: the plan, rows, timeline, print and CSV say "Pixel size is not set for <camera>, so no exposure is shown. Add it in Gear." ## Layout check (real browser)

It needs Playwright for Python and its Chromium, which the repo does not depend on:

    ~/tools/shots/bin/python docs/guides/planner-layout-check.py

It starts its own `next dev` on a free port and stops it afterwards; pass a URL to use a server you already run. Exit code 0 means every check passed.

It also measures, after every key and every drag step, the page position of the four buttons and the target list (typing 500 in Start, 91 and 95 in Height, slider drags), that Clear horizon and Add a blocked arc leave Save horizon in place, that no message line is clipped at 1280, 1024, 768, 640, 390 and 360 px, that a click on Save horizon under a toast works and the toast clears, and that Edit horizon lands below the site header.

## Sign-in and owner gate

- Signing in (Google, Auth.js, JWT) is optional. Every visitor gets the planner and the AI night plan with guest caps; owners (allowlisted Google accounts) are uncapped. See `planner-ai-night-plan.md`.
- `/planner` is prerendered. The sign-in control asks `/api/planner/session` after load (200 always, `private, no-store`: `{signedIn:false, configured}` signed out, or `owner` and `login`). The control is a fixed 44 px row in the page header, beside the title; `scripts/planner-auth-shift-check.py` proves the `h1` does not move.
- Owners are Google account ids (`sub`) in `PLANNER_OWNER_GOOGLE_SUB` (comma list), or verified emails in `PLANNER_OWNER_GOOGLE_EMAIL`. Display names are never matched. Unset, empty or malformed entries mean nobody.
- A route that must stay owner-only calls `requireOwner()` first (`src/lib/planner-auth/require-user.ts`): 401 signed out, 403 signed in but not an owner. A route open to guests with caps (the AI night plan) uses `identifyCaller()` and must count every paid call. `requireUser()` alone is not a gate.
- Env: `AUTH_SECRET`, `AUTH_GOOGLE_ID`, `AUTH_GOOGLE_SECRET`, `AUTH_URL` (or `AUTH_TRUST_HOST=true` off Vercel), `PLANNER_OWNER_GOOGLE_SUB`, `PLANNER_OWNER_GOOGLE_EMAIL`. Google OAuth redirect URI: `<AUTH_URL>/api/auth/callback/google`.
- With JS off the button posts without a CSRF token; Auth.js redirects to its own sign-in page, where the Google button works.
