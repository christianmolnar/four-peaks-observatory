# Imaging planner preview (`/planner`)

Reachable by URL only; not in the header, `noindex`. All state is in the browser (localStorage keys `fpo-planner-profile-v1`, `fpo-planner-captured-v1`, `fpo-planner-itinerary-v1`). No server code.

## Manual check

1. `npm run dev`, open `/planner`.
2. Date defaults to tonight at the site (from its longitude; before 06:00 site time it is the night that began yesterday), whatever the browser's zone. Times are shown in the browser's time zone, because the profile's site has no time zone field.
3. Horizon editor (Start, End, Height). Typing and sliding edit a draft; only "Save horizon" stores it.
   - Click "Edit horizon" next to the "Horizon:" line in Tonight: the page jumps to the editor.
   - Type `200` in Start, key by key: the slider and the polar chart in the editor follow as soon as the text is a valid whole number. The status line says "Unsaved changes". The "Horizon:" line, the target list and the altitude chart plan from the saved arc, so they change only when you click "Save horizon" (or press Enter in a box while the form is valid). Nothing is stored before that.
   - A slider follows its own box whenever the box holds a valid number, so the arrow keys step one degree at a time across the other end (Start 318, then ArrowRight: 319, 320, 321 ...).
   - Type `500` in Start: a line under the box says "Use 0 to 359 degrees.", the slider goes back to the saved Start and the plan never left it, "Save horizon" is greyed and the status line says "Fix the highlighted box to save". Same for `361`, for `91` or `95` in Height ("Use 0 to 90 degrees."), for an empty box, and for `1.5` ("Whole degrees only.").
   - Type `320` in Start while End is 320: "Start and End must differ." under both boxes.
   - Leaving a box (Tab, a click elsewhere) and Escape do nothing. Pressing Enter in a box saves only if the form is valid.
   - The buttons and the target list keep their page position on every key, because the list does not follow the draft and every message line has its height reserved. So the first click on "Discard changes", "Use sample horizon", "Clear horizon" or "Save horizon" works right after bad typing. "Discard changes" puts the three boxes back to the saved arc.
   - "Use sample horizon" loads the sample arc into the boxes as an unsaved draft ("Discard changes" undoes it) and puts Minimum altitude back to 20. The whole-profile wipe is "Replace profile with sample" in the Profile section.
   - A different site, an import and "Replace profile with sample" also set the boxes from the saved arc and Minimum altitude to 20; nothing typed survives.
   - Tab order: Start box, Start slider, End box, End slider, Height box, Height slider, Save, Discard, Use sample horizon, Clear horizon, "Horizon as a table".
   - Minimum altitude (Tonight) works on its own: it applies as soon as the text is a whole number from 0 to 89, with no Save. While it is invalid the plan keeps the value that was in effect when the current run of typing began, never a half-typed prefix. A run ends when the box gets focus, on Enter, or after a pause of about 0.6 s with no keystroke; only then does the kept value move to the current valid number. So emptying the box with Backspace (45 in effect, or the default 20) still plans with 45 (or 20), and within one run of typing the message names the value from before the run, and the line under the box names it ("Use 0 to 89. Planning with 30 until fixed."). Its message slot reserves two lines.
   - Bad Minimum altitude does not block "Save horizon".
4. Raise the height to 80 and save: southern targets drop out of the list. "Clear horizon" is also a draft: badge "Horizon not set" and the flat minimum altitude in each "why" once saved; "Discard changes" brings the arc back.
5. "Save horizon" then reload: the arc persists, status line empty. "Replace profile with sample" (Profile section, asks first) restores the default.
6. Targets: pick the train "C11 f/10 + ASI2600MC Duo". Targets that do not fit the field are not listed. Tick "Show targets that do not fit": they appear below every row that fits, and their text reads "Does not fit this setup (...)" under "Why it is listed". Rows that fit still read "Why recommended".
7. "Export CSV": header row, one row per listed target, names with commas quoted.
8. Filter and Exposure (select a target row first; the panel sits below the altitude chart):
   - "Filter" in Tonight lists "No filter" and the twelve sample filters; the choice belongs to the train, is saved with the profile, and shows again after a reload. A smart scope has the box disabled ("Built in"). A profile saved before filters existed has none: the line under the box reads "No filters. Use Replace profile with sample." (whole, at every width from 390 to 2560 px), and "Replace profile with sample" loads the sample list (it also resets the horizon).
   - The Exposure panel has "Sky darkness (Bortle class)" (starts at 6, an assumption, not saved), a line describing the chosen filter (unknown values say "unknown" or "not published"), and three mode cards: Quick & Beautiful, Balanced (chosen at first) and Deep Project. Each card shows sub length, sub count, total light, overhead (setup, dithers, autofocus, meridian flip), elapsed time and finish time, every row labelled "estimate" with a range (sub count: the frames needed if the subs are at the long or the short end of the sub-length range; finish: spans the whole elapsed range, so it is a spread of tens of minutes, not a minute).
   - The meridian flip is added only when the target really crosses the meridian (hour angle zero) inside the session. Try North America Nebula on 2026-12-15 with the HyperStar train: it is already past the meridian, no flip, Quick overhead 33.7 min. Thor's Helmet crosses 43 minutes into its window: Quick shows the flip and 10 more minutes.
   - Tab from the Bortle box lands on the chosen card; the arrow keys move the choice, a click works too, and the word "Selected" marks it (not colour only). The cards sit side by side from 1024 px and stack in one column below it. Changing the mode or the filter moves nothing on the page at 1280, 768 and 390 px (checked by the layout script): the card rows hold the height of their longest wrap, and the warnings list is a box of fixed height with its own scrollbar. When the box has more than it shows, the line under it says "N more below, scroll" (on a phone the scrollbar is a thin overlay, so the words matter); the line is always there, empty otherwise, so it moves nothing.
   - "Warnings and notes" lists, each tagged Warning or Note: filter rated slower than the train (try the HyperStar train with "Optolong L-eXtreme (standard)"; the CLS CCD gives none), no UV/IR cut (the "C11 + 0.7x reducer + ASI533MC" train with no filter or "IDAS LPS-P2"; "Baader UV/IR cut" clears it), a visual filter on a colour camera (try "Apertura Moon and Skyglow"), image scale, Moon, usable-time limits, short-session and Ou4 notes.
   - "What more time buys": 30, 60, 90, 120 minutes at x1.00, x1.41, x1.73, x2.00 of the signal-to-noise (square root of time: 4 times the time is 2 times the signal-to-noise), with a range and the assumption written under it. The gain column ("estimate (range)") gives +41%, +22%, +15% as the ideal and a lower value with 30 per cent of the gain lost (+29%, +17%, +12%). There is no best stop time. On a phone the table has four columns (the range sits under the value) and does not scroll sideways.
   - Planets show a one-line message (deep-sky only); smart scopes say an optical train is needed.
   - The sub length range stays between 10 and 300 s, the module's own limits. A filter whose kind is not set and whose name says Sky Glow (Orion sells a visual and an imaging version) gets a note on a colour camera, never a warning.
   - Surface brightness is not in the catalog, so Quick says the short-session rule cannot rank the target (clusters and planetary nebulae count as bright).
9. Import a profile with `latitude: 120`: the error names `$.sites[0].latitude`.
10. Planets (below the Night itinerary; the profile's first train is the planetary train, C11 + ASI676MC):
   - Eight cards in the spec order: Jupiter, Saturn, Mars, Venus, Mercury, Uranus, Neptune, Moon. The page opens on the first planet that is clear of your horizon. Arrow keys move between cards, a click works, the word "Selected" marks the choice. Every card line is computed.
   - The detail below holds apparent diameter (and its size in pixels on the chosen train), phase or illuminated fraction, opposition or greatest elongation (nearest one, in days), culmination, minutes clear of your horizon (from the saved arc) and how many of them are above the no-ADC altitude, Saturn's ring tilt (the size only; the library does not say which face shows), the clip length limit and the image scale. Each label says computed, or computed with a named basis (rotation period sourced, seeing assumed).
   - The windows use the same astronomical night as the target list. Venus, Mercury and the early Moon are twilight objects and may show as not clear when they could be imaged earlier; that is not computed. There is no Jupiter Great Red Spot transit (no verified longitude model).
   - The eight panels sit in one grid cell and only the chosen one is visible, so choosing another planet moves nothing. The hidden ones are removed from the tab order and from assistive technology.
   - The altitude chart for the chosen planet has a title, a description and a table behind "Altitude as a table".
   - The checklist (Space ticks a box; ticks are not saved) ends each line with its basis: computed, sourced, assumption, practice or not verified. It names the scope and camera of the chosen train from the profile (pick the ASI533MC reducer train: it says ASI533MC, not ASI676MC). The exposure line is per body: Jupiter keeps a 10 ms assumption; Saturn, Mars, Uranus and Neptune quote one university club's published setting as the order of magnitude (sourced; Saturn, Uranus and Neptune are told they need longer than Jupiter); Venus, Mercury and the Moon give no number. Clip length (up to a number of seconds, from rotation) and session length (about 30 minutes at the telescope) are separate lines. ASIAIR appears once, as not verified. The train lines say to start native; the 2.5x Powermate row is nominal because the Powermate is a 1.25 inch eyepiece amplifier with no stated camera spacing.
   - Check the numbers against a second source: `src/planner/planets/horizons.fixture.json` holds JPL Horizons values for the sample site (diameter, illuminated fraction, azimuth, altitude, elongation, transit times) and `planets.test.ts` compares them.
11. Night itinerary (below the Exposure panel):
   - Pick a target in "Target to add" and press "Add to itinerary" (the new slot starts on the train chosen at the top, with its filter). The Moon is the last entry of the list. Up to eight slots. A smart scope train turns the button off and says why.
   - Each slot shows start and end (estimate), the light it plans (sub length, count, minutes, from the exposure module), the minutes of changeover before it, and chips for what needs a look. Per slot: train, filter, mode, a note (200 characters), Up, Down, Details, Remove.
   - Up and Down work with Enter or Space; focus stays on the pressed button. At either end the button is marked disabled but stays focusable and does nothing. Start times follow the order at once.
   - Changeover between slots (all estimates, `src/planner/itinerary/constants.ts`): slew and centre 3 min; filter change 2 min; train change 15 min; refocus 3 min after either. Setup (30 min) is before the first slot and not counted.
   - Warnings: "Waits" (note: the target is not clear yet, a planet is waiting to be centred on its highest point, or a short first window is skipped for a later one), "Overlaps window" (warning: the slots before used part of a window that closes, so too little is left for the mode; it does not show while the light still reaches the mode's range), "Cut short", "Meridian flip" (the exposure module's flip time, for planets as well as deep-sky targets: the planet's real crossing inside the slot), "No time" (the window closed before this slot's turn; the sentence says when a changeover ran past the close). The Details box shows the sentences; it is as tall as the longest possible set, so nothing moves.
   - Try Orion Nebula then Triangulum Galaxy on 2026-12-15 with the C11 + 0.7x reducer + ASI533MC train: the second slot overlaps its window (Triangulum closes 07:11 UTC; Orion ends 07:00). Swap them: the overlap goes.
   - Try Andromeda Galaxy then Orion Nebula: Orion's first window (03:17 to 04:06 UTC) would give 27 minutes of Balanced's 60 to 120, so the slot waits for the free window from 05:25 and says so (the note names both windows). A slot waits for a later window only when it reaches the mode's range; otherwise it keeps the first, and when a later window would give more light the Cut short sentence names it (try Orion Nebula, Deep, on 2027-10-03: it keeps the 45 minute window and names the later one, 10:13 to 12:00 UTC, which would give 102 of the 120 the mode needs).
   - A planet slot is 20 minutes of clips, centred on the planet's highest point where its window allows, in whichever window of the night puts it highest (Neptune on 2027-09-28 waits for the window that holds its 57° culmination, 07:17 UTC, not the 36° one before it). When the window ends before the peak, the sentence says "the highest Neptune reaches in this window" (try 2027-06-12), never "highest point". (Saturn on 2026-12-15 starts 10 minutes before it crosses the meridian, 02:21 UTC). Add Neptune alone: its slot crosses the meridian (01:56 UTC), shows "Meridian flip" and is 30 minutes long (20 of clips and the 10 minute flip). The Moon slot (the Moon drops below 20° at 02:25 UTC) crosses nothing and takes 20.
   - "Why this order" is one sentence: sorted by when each target clears the horizon, or your own order with the first pair that is out of order named.
   - Saved in this browser (`fpo-planner-itinerary-v1`, version 1). A saved itinerary that fails the check is reported with its field path (for example `$.items[0].mode`) and the stored text stays until you change something.

- `npm test` covers the plan functions (including the fit sort), CSV, storage and validation helpers, a server render of the page for fixed dates, and DOM tests (user-event, jsdom).
- `src/app/planner/HorizonEditor.test.tsx` types key by key through the whole page: every row of the round-2 and round-3 failure tables (bad values, Discard, Use sample horizon, Replace profile, site change, import, Minimum altitude after each), Save and reload, Enter, blur, tab order.
- `src/app/planner/PlannerApp.fit.test.tsx`: targets that do not fit are hidden by default, sort last, and are not "recommended".
- `src/app/planner/PlannerApp.wiring.test.tsx`: default date, blocked or full storage, CSV time format.
- `src/planner/exposure/exposure.test.ts`: the estimate with fixed inputs, every warning branch, the edge-shift formula (f/1.9: Ha 5.3 nm, OIII 4.1 nm), the marginal table. `src/app/planner/PlannerApp.exposure.test.tsx`: the panel and Filter box with real key events, saved choice, smart scope, planets.
- `src/planner/planets`: apparent diameter, phase, elongation, ring tilt, transit and opposition against the Horizons fixture; the rotation limit, sampling and dispersion formulas; the cards for one night; the guide text (every line has a basis, ASIAIR only as not verified). `src/planner/itinerary`: the schedule, changeovers, warnings, reorder and the saved form. `src/app/planner/PlannerApp.planets.test.tsx` and `PlannerApp.itinerary.test.tsx`: both sections with real key events.
- `src/planner/profile`: the v1 to v2 migration (a saved v1 profile keeps all its data and gets an empty filter list) and filter validation.

## Layout check (real browser)

jsdom has no layout, so it cannot see a button move. `docs/guides/planner-layout-check.py` drives headless Chromium with real key presses and a real mouse at 1280 and 390 px (the Exposure and the Planets and Itinerary scripts below also run at 768 px): Save, Discard, Use sample horizon and Clear horizon keep identical bounding boxes before and after each rejected value, and a real mouse click (90 ms hold, aimed in the top fifth of the button) works first time after bad typing. It needs Playwright for Python and its Chromium, which the repo does not depend on:

    ~/tools/shots/bin/python docs/guides/planner-layout-check.py

It starts its own `next dev` on a free port and stops it afterwards; pass a URL to use a server you already run. Exit code 0 means every check passed.

It also measures, after every key and every drag step, the page position of the four buttons and the target list (typing 500 in Start, 91 and 95 in Height, slider drags), that Clear horizon and Add a blocked arc leave Save horizon in place, that no message line is clipped at 1280, 1024, 768, 640, 390 and 360 px, that a click on Save horizon under a toast works and the toast clears, and that Edit horizon lands below the site header.
